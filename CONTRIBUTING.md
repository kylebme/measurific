# Contributing

Issues and pull requests are welcome. For larger changes, please open an issue
first to discuss the approach.

## Setup

Follow **Development** in the [README](README.md). One virtual environment in
`app/.venv` covers the app and every package.

## Tests

Run the tests for whatever you change before opening a pull request:

| Area | Command |
|---|---|
| App (UI, Electron) | `cd app && npm test && npx tsc -b` |
| App worker | `cd app && .venv/bin/python -m pytest -q python` |
| A Python package | `cd packages/<name> && ../../app/.venv/bin/python -m pytest -q` |
| Synthetic shapes | `cd research/synthetic-shapes && ../../app/.venv/bin/python -m pytest -q` |
| Camera bridge | see [camera-bridge/README.md](camera-bridge/README.md) |

CI runs the Python package tests on every push and pull request, and builds and
smoke-tests the installers on pull requests that touch the app or the bundled
packages.

## Models and data

Training data is generated by the tools in [research/](research/README.md) and
is not stored in this repository. Released model checkpoints and their ONNX
exports live with their packages (`packages/contour-model/release-*`,
`packages/edge-model/models`). If you change a model the app bundles, re-export
it and run the parity checks described in [app/README.md](app/README.md).
